# План впровадження підтримки бездротових реле (Shelly) з автопошуком

Цей документ описує стратегію переходу до гібридної системи керування дзвінками, що підтримує як фізичні USB-реле, так і Wi-Fi пристрої Shelly з автоматичним виявленням у мережі.

## 1. Архітектурна трансформація
Зараз клас `RelayController` жорстко прив'язаний до USB/HID. Необхідно впровадити рівень абстракції:

1.  **Інтерфейс `RelayDevice`**:
    *   `void turnOn()` / `void turnOff()`
    *   `boolean isConnected()`
    *   `String getDisplayName()`
2.  **Реалізації**:
    *   `UsbRelayDevice`: існуюча логіка HID.
    *   `ShellyRelayDevice`: нова логіка через HTTP запити.

## 2. Автоматичне виявлення (Discovery)
Для реалізації принципу "Plug & Play" буде використано протокол **mDNS (Multicast DNS)**.

*   **Бібліотека**: Додати `jmdns` у `pom.xml`.
*   **Механізм**: Shelly анонсують сервіс `_http._tcp.local.`. Програма буде фільтрувати пристрої за назвою хоста (що містить "shelly") та отримувати їхні IP-адреси автоматично.

## 3. Керування Shelly через API
Програма буде автоматично визначати покоління пристрою під час пошуку через запит до `http://[IP]/shelly`:
*   **Gen 1 (Shelly 1/PM)**: Відсутнє поле `"gen"` у відповіді. Використовуємо шлях: `http://[IP]/relay/0?turn=on`.
*   **Gen 2/3 (Plus/Pro)**: Поле `"gen": 2` або `3` у відповіді. Використовуємо RPC шлях: `http://[IP]/rpc/Relay.Set?id=0&toggle=after&on=true`.

Це забезпечує повну сумісність з будь-яким обладнанням Shelly без ручного налаштування користувачем.

## 4. Оновлення інтерфейсу (SystemView)
У розділі "Система" додати новий блок "КЕРУВАННЯ ПРИСТРОЄМ ВИКОНАННЯ":

*   **Segmented Control**: [ USB ] | [ WI-FI (SHELLY) ]
*   **Для Wi-Fi режиму**:
    *   Кнопка "ПОШУК РЕЛЕ У МЕРЕЖІ" з анімацією завантаження.
    *   Випадаючий список знайдених пристроїв (наприклад: "Shelly Plus 1 - 192.168.1.50").
    *   Індикатор сигналу Wi-Fi та статусу онлайн.

## 5. Технічні кроки реалізації

### Крок 1: Залежності (pom.xml)
```xml
<dependency>
    <groupId>org.jmdns</groupId>
    <artifactId>jmdns</artifactId>
    <version>3.5.9</version>
</dependency>
```

### Крок 2: Створення Discovery Service
Створити `NetworkDiscoveryService`, який у фоновому режимі сканує мережу та повертає список об'єктів `ShellyDevice`.

### Крок 3: Рефакторинг SignalService
Змінити `SignalService`, щоб він звертався до абстрактного `RelayDevice`, не знаючи, як саме передається сигнал (через кабель чи повітря).

## 6. Як впровадити (Інструкція для Gemini)
Коли буде достатньо ресурсів, надішли цей файл мені з командою:
*"Реалізуй підтримку бездротових реле згідно з планом STRATEGY_WIRELESS_RELAY.md. Впровадь інтерфейс RelayDevice, додай бібліотеку jmdns для автопошуку Shelly та онови інтерфейс SystemView для вибору типу підключення."*
