# Аналіз та рекомендації щодо впровадження нових медіа-тригерів

Ми проаналізували файл [MEDIA_TRIGGER_IDEAS.md](file:///C:/school_bell/untitled/MEDIA_TRIGGER_IDEAS.md) та архітектуру запуску медіа-подій у класах [MediaSchedulerService](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/service/MediaSchedulerService.java) та [MediaEventEditorDialog](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/ui/MediaEventEditorDialog.java). 

Загалом, запропоновані ідеї повністю вирішують проблему "запізнілого ввімкнення комп'ютера" та динамічного підлаштування під перший урок. Проте, для якісної та безвідмовної реалізації варто врахувати кілька важливих технічних нюансів та кращих практик.

---

## 1. Детальний аналіз запропонованих ідей

### Ідея 1: Тригер "У проміжку часу" (RANGE)
Цей варіант ідеально підходить для фонової ранкової музики (наприклад, з `08:00` до `08:25`).
*   **Як це вирішує проблему:** Замість точкової перевірки (`nowStr.equals(event.time())`), система перевіряє входження в інтервал: `now >= start && now < end`. Якщо комп'ютер увімкнули о `08:02`, умова все одно виконається.
*   **Рекомендація щодо UI:** Додати прапорець *"Запускати при старті програми"* (якщо він вимкнений — музика гратиме лише якщо програма вже була запущена до початку проміжку).

### Ідея 2: Тригер "Перед першим уроком" (BEFORE_FIRST_LESSON)
Підходить для коротких інформаційних сповіщень чи гімну, час яких залежить від розкладу конкретного дня.
*   **Як це вирішує проблему:** Система динамічно вираховує час запуску за формулою: `Час_Першого_Уроку - Зміщення`. 
*   **Захист від запізнення:** Введення параметра *"Допустиме запізнення"* (наприклад, 3 хв) не дозволить увімкнути бадьору музику/оголошення посеред уроку, якщо комп'ютер увімкнули занадто пізно (наприклад, о `08:32` при початку уроку о `08:30`).

## 2. Приховані технічні нюанси та ризики (Що варто додати)

### ⚠️ Запобігання повторному запуску (Повторний тригер)
Оскільки [MediaSchedulerService](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/service/MediaSchedulerService.java) кожну секунду або хвилину перевіряє умови запуску:
1.  **Проблема:** Якщо ми перебуваємо всередині інтервалу `[08:00 - 08:25]`, тригер буде спрацьовувати знову й знову кожну хвилину, перезапускаючи плеєр.
2.  **Проблема 2:** Якщо користувач вручну вимкнув музику (натиснув "Стоп"), система не повинна автоматично вмикати її знову через хвилину.
3.  **Рішення:** Для кожного тригера типу `RANGE` та `BEFORE_FIRST_LESSON` необхідно зберігати в пам'яті (або базі даних) прапорець/дату останнього запуску (наприклад, `lastTriggeredDate`), щоб подія гарантовано запускалася **не більше одного разу на день**.

### 📶 Старт онлайн-радіо та затримка мережі
Якщо як джерело обрано **Онлайн Радіо** (клас [RadioSelectionDialog](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/ui/RadioSelectionDialog.java)):
*   При холодному старті Windows мережа (Wi-Fi або Ethernet) може ініціалізуватися від 10 до 30 секунд.
*   Якщо медіа-подія запуститься в перші секунди роботи програми, підключення до радіостанції впаде з помилкою мережі.
*   **Рішення:** Затримка після старту програми (`Затримка після старту програми` в UI) має бути не менше 15–20 секунд за замовчуванням для радіопотоків, або система має перевіряти наявність інтернет-з'єднання перед початком відтворення.

### 🔊 Плавний вхід звуку (Fade-in)
*   Різкий запуск музики на повну гучність відразу після завантаження операційної системи може налякати людей у коридорах.
*   **Рішення:** Для ранкової музики на старті бажано застосовувати плавне наростання гучності (Fade-in) протягом 5–10 секунд.

### 🛑 Пріоритет надзвичайних ситуацій (НС та Тривога)
*   Необхідно суворо інтегрувати перевірку стану тривоги. У поточній версії [MediaSchedulerService](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/service/MediaSchedulerService.java#L52-L60) це вже частково реалізовано:
    ```java
    String alertType = mainApp.getSignalService().getCurrentAlertType();
    if ("AIR_RAID".equals(alertType) || "EMERGENCY".equals(alertType)) { ... }
    ```
    Потрібно переконатися, що нові тригери також поважають це обмеження і не запускаються під час повітряної тривоги.

## 3. Пропозиція щодо спрощення схеми БД
Щоб не робити складних міграцій бази даних `school_bell.db` для класу [MediaEvent](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/model/MediaEvent.java):
*   Для тригера **"У проміжку часу"** (`RANGE`):
    *   Поле `time` можна використовувати для збереження обох значень у форматі `HH:mm-HH:mm` (наприклад, `08:00-08:25`). При парсингу розділяти рядок через дефіс `-`.
*   Для тригера **"Перед першим уроком"** (`BEFORE_FIRST_LESSON`):
    *   Поле `type` встановити в `"FIRST_LESSON"`.
    *   Поле `breakOffset` використовувати для збереження зміщення у хвилинах (наприклад, `5`).
    *   Поле `time` використовувати для збереження допустимого запізнення (наприклад, `3` хвилини).

Це дозволить впровадити фічу без необхідності міняти структуру таблиці в [DatabaseManager](file:///C:/school_bell/untitled/src/main/java/com/schoolbell/service/DatabaseManager.java).
