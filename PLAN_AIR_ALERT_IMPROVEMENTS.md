# План виправлення та вдосконалення автоматизації повітряної тривоги (AirAlertService)

## 1. Опис проблеми

Користувач повідомив про небажану поведінку:
> *«Автоматизована повітряна тривога подала сигнал про початок тривоги, а потім орієнтовно через 30 секунд знову подала сигнал.»*

Також виявлено:
> *«У логах періодично з'являється помилка 429 Too Many Requests, після якої фіксується "Зв'язок з API тривог відновлено".»*
> *«У школі немає колонок/аудіосистеми, звук подається виключно через реле на фізичний дзвінок.»*

---

## 2. Аналіз причин (Root Cause Analysis)

Під час дослідження API Ubilling (`https://ubilling.net.ua/aerialalerts/?source=default&raw`), аналізу мережевих логів та коду сервісів виявлено **п'ять взаємопов'язаних факторів**:

### Фактор 1: Відсутність гістерезису / дебаунсу відбою (Миттєвий фальшивий Відбій)
- В `AirAlertService.java` опитування відбувається кожні **6 секунд**.
- Якщо `currentAlert == false` хоча б під час **одного циклу опитування** (6 секунд), сервіс **миттєво**:
  1. Скидає `lastAlertState = false`.
  2. Викликає `signalService.runAirRaidClearSignal()` (запускає сигнал відбою).
- Якщо на наступному або через один цикл (через 6–12 секунд) тривога знову `true`, сервіс сприймає це як **нову тривогу** і знову викликає `signalService.runAirRaidSignal()`.

### Фактор 2: Перехід між рівнями загрози (`yellow` -> `red`) у сирому Ubilling
- В Україні діє диференційована система: `yellow` (дрони) та `red` (ракети).
- У сирому API від Вадима Клименка (через Ubilling) при ескалації тривоги попередня тривога закривається (виставляється `disabled_at` та `enabled: false`), а нова відкривається з `alert_level: "red"`.
- У це коротке "вікно" між оновленнями кешу API віддає `enabled: false`. Без дебаунсу програма вмикає відбій, а через 10–20 секунд при отриманні червоного рівня — повторну тривогу.

### Фактор 3: HTTP 429 Too Many Requests на шлюзі Ubilling
- Сервер Ubilling обмежує запити: **не більше 2 rps на зовнішній IP**.
- Усі школи та користувачі за одним провайдерським NAT ділять цей ліміт. Під час масованих обстрілів сервери перевантажуються.
- При 429 втрачається зв'язок на кілька циклів. Коли зв'язок відновлюється (лог *"Зв'язок з API тривог відновлено"*), статус може миттєво стрибнути `Відбій -> Тривога`.

### Фактор 4: Однаковий патерн фізичних дзвінків реле (Тривога і Відбій звучать абсолютно ідентично)
- **Контекст школи**: у школі **немає аудіосистеми**, використовується **лише фізичний дзвінок через реле**!
- У `SignalService.java`:
  - **Початок тривоги (`runAirRaidSignal`)**: 3 дзвінки по 3 секунди з паузою 1 секунда (разом ~11 секунд).
  - **Відбій тривоги (`runAirRaidClearSignal`)**: **рівно ті самі 3 дзвінки по 3 секунди з паузою 1 секунда**.
- **Наслідок**: коли стався стрибок API, програма через 20–30 секунд подала сигнал **Відбою**. Оскільки голосового супроводу немає, люди почули знову 3 дзвінки і сприйняли це як **повторний сигнал тривоги**!

### Фактор 5: Недоліки парсингу JSON та логіки Область / Район
1. Поле `alert_level` не зчитується у старому парсері Ubilling.
2. Область без району: на рівні області стояло `enabled: false`, навіть коли всі райони в тривозі.

## 3. Нове рішення: Власний Cloudflare Worker на базі офіційного UkraineAlarm API v3

Розгорнуто захищений проксі-кешер:
🔗 **`https://schoolbell-alert.12asic12.workers.dev/`**

### Переваги нового воркера:
1. **Повна безпека API-ключа**: секретний токен UkraineAlarm надійно зашифрований у Cloudflare Secrets і не публікується у відкритому коді на GitHub.
2. **Кешування на 5 секунд**: Cloudflare віддає закешовану відповідь клієнтам, а до `api.ukrainealarm.com` іде максимум **1 запит на 5 секунд**. Жодного ризику отримати 429 Too Many Requests!
3. **Плавний перехід Yellow / Red**: офіційний API UkraineAlarm v3 тримає обидва рівні в масиві `activeAlertLevels` без розриву тривоги:
   ```json
   {
     "regionName": "Покровський район",
     "activeAlerts": [{
       "activeAlertLevels": [
         { "alertLevel": "Red", "reason": "Ракетна загроза (червоний рівень)" },
         { "alertLevel": "Yellow", "reason": "Дронова загроза (жовтий рівень)" }
       ]
     }]
   }
   ```

## 4. Порівняльний аналіз: `/api/v3/alerts` (весь список) проти `/api/v3/alerts/{regionId}`

Користувач запропонував запитувати конкретний регіон за ID: `/api/v3/alerts/{regionId}`.
Ось порівняння обох підходів:

| Критерій | `/api/v3/alerts` (Загальний список активних тривог) | `/api/v3/alerts/{regionId}` (Один регіон за ID) |
| :--- | :--- | :--- |
| **Ефективність кешу Cloudflare** | ⭐ **100% Cache Hit**. Усі школи запитують один URL. До UkraineAlarm іде лише **1 запит на 5 секунд** на всю Україну. | ❌ **Пробиття кешу**. Якщо 50 шкіл запитують 50 різних ID, Cloudflare робить 50 окремих запитів до UkraineAlarm за 5 сек (10 rps), що перевищує ліміт ключа і спричинить 429 на стороні воркера! |
| **Ієрархія тривог (Область + Район)** | ⭐ **Ідеально**. Якщо оголошено ракетну небезпеку на всю область (Київська обл.), а школа знаходиться в районі (Броварський р-н) — у загальному списку є і область, і район. Додаток гарантовано бачить загрозу. | ❌ **Ризик пропуску**. Якщо школа запитує тільки `{districtId}`, а тривога оголошена на `{oblastId}` (або навпаки) — потрібно робити 2 окремих запити за різними ID, або тривогу буде пропущено. |
| **Складність конфігурації** | ⭐ **Нульова**. Працює за назвами районів із вже існуючого довідника `RegionDirectory.java`. Не потрібно шукати та хардкодити числові ID всіх 136+ районів. | ❌ **Висока**. Потрібно створити і підтримувати повну таблицю числових `regionId` UkraineAlarm для кожного району і громади. |
| **Розмір даних та швидкість** | Розмір: лише активні тривоги (~30–40 КБ, стиснуто в gzip ~3 КБ). Парсинг у Java через Gson займає **~0.5 мілісекунди**! | Розмір: ~0.5 КБ. Різниця в швидкості парсингу менше 0.3 мс. |

### Оптимальне рішення (Компроміс):
- Додаток за замовчуванням опитує `https://schoolbell-alert.12asic12.workers.dev/`.
- Загальний список містить лише актуальні тривоги (масив із 30–50 об'єктів), тому передача та парсинг відбуваються миттєво.
- Якщо в майбутньому знадобиться фільтрація, її можна робити прямо на стороні Cloudflare Worker: воркер бере закешований загальний список і повертає відфільтрований результат, не роблячи зайвих запитів до UkraineAlarm.

## 5. Покроковий план реалізації

### Крок 1. Модернізація `AirAlertService.java` під новий Cloudflare Worker
- Оновити `API_URL = "https://schoolbell-alert.12asic12.workers.dev/"`.
- **Парсинг масиву UkraineAlarm**:
  - Відповідь є JSON-масивом активних тривог `[{ regionName: "...", activeAlerts: [...] }]`.
  - Якщо обрано конкретний район: перевіряємо наявність у списку елемента з назвою району **АБО** елемента з назвою області (`regionName.equals(selectedRegion)`).
  - Якщо обрано область без району: перевіряємо, чи є в списку сама область **АБО** будь-який район цієї області (з довідника `RegionDirectory.UKRAINE_REGIONS`).
- **Витягування та логування причини тривоги (`reason`)**:
  - З поля `activeAlertLevels` зчитуємо значення `reason` (наприклад, *"Дронова загроза (жовтий рівень)"* або *"Ракетна загроза (червоний рівень)"*).
  - Запис у системний журнал програми:
    `LIVE: ВИЯВЛЕНО ТРИВОГУ: Київська область/Білоцерківський район [Дронова загроза (жовтий рівень)]`
  - **Інформативне логування ескалації**: якщо під час активної тривоги рівень змінюється (наприклад, з жовтого на червоний), записуємо в журнал:
    `LIVE: ЗМІНА РІВНЯ ЗАГРОЗИ: Київська область/Білоцерківський район [Ракетна загроза (червоний рівень)]`
    при цьому **дзвінок повторно НЕ дзвонить**, а користувач чітко бачить причину в системному журналі.

### Крок 2. Debounce (підтвердження) Відбою на 25 секунд
- **Тривога (`currentAlert == true`)**: вмикається **миттєво (0 затримок)**.
- **Відбій (`currentAlert == false`)**:
  - Лічильник `clearConfirmationCount`.
  - Відбій подається **лише після 4 послідовних циклів відсутності тривоги** (24–30 секунд).
  - Будь-який короткочасний сплеск або відновлення тривоги скидає лічильник і зберігає статус тривоги без повторних дзвінків.

### Крок 3. Диференціація дзвінків реле в `SignalService.java`
- Оскільки в школі працює лише дзвінок через реле:
  - **Початок тривоги**: 3 дзвінки по 3 секунди з паузою 1 сек (сигнал евакуації).
  - **Відбій тривоги**: **1 протяжний довгий дзвінок на 5–6 секунд** (або 2 коротких).
  - Персонал і діти більше ніколи не сплутають відбій із тривогою.

### Крок 4. Захист від помилок мережі (Fail-Safe)
- При помилках HTTP або таймаутах стан тривоги **заморожується**.
- Після відновлення зв'язку відбій оголошується лише після повного проходження дебаунсу.

### Крок 5. Unit-тести
- Покрити в `AirAlertServiceTest.java`:
  - Парсинг масиву UkraineAlarm (район, область, рівні Yellow/Red).
  - Тест на дебаунс відбою.
  - Пріоритет загальнообласної тривоги для району.
