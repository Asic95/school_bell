# Ресерч: Інтеграція онлайн-радіо в систему School Bell (Оновлено)

## Опис запиту
Користувачі хочуть мати можливість автоматично відтворювати онлайн-радіо в певний час (наприклад, на перервах) через обрані в системі пристрої відтворення (шкільні колонки).

## Поточний стан
- Система використовує `AudioService` на базі `javax.sound.sampled` (PCM Engine).
- Підтримуються локальні файли MP3, WAV, AAC через встановлені SPI.
- Реалізовано програмне керування гучністю та плавне затухання (fading).

## Технічна архітектура (Гібридний підхід)

### 1. Джерело даних: Radio Browser API
Для забезпечення величезного вибору станцій без ручного пошуку URL:
- **Джерело:** [Radio-Browser.info](https://www.radio-browser.info/) (Open Source, Public Domain / CC0).
- **Кешування:** Система завантажує JSON-каталог станцій України (`country == "Ukraine"`) та зберігає його локально.
- **Фільтрація:** При відображенні каталогу показувати лише станції з `codec == "MP3"` (або AAC) та `lastcheckok == 1` для гарантії стабільності.

### 2. Сховище (Database)
- **Каталог (JSON):** Тимчасовий файл-кеш для пошуку.
- **Вибране (SQLite):** Коли користувач обирає станцію з каталогу, вона копіюється в таблицю `radio_stations`.
  - Поля: `id`, `name`, `url_resolved`, `favicon_url`.
  - Це забезпечує цілісність посилань у розкладі, навіть якщо зовнішній API зміниться.

### 3. Механізм відтворення в `AudioService`
- **Потік:** Використання `AudioSystem.getAudioInputStream(new URL(url).openStream())`.
- **Буферизація:** Обов'язкове використання `BufferedInputStream` (мінімум 1 МБ) для компенсації мікро-лагів мережі.
- **Стійкість (Resilience):** Реалізація логіки **Auto-Reconnect**. Якщо з'єднання розірвано до закінчення запланованого часу — спробувати перепідключитися.
- **Метадані:** Можлива потреба у фільтрації ICY-метаданих, щоб уникнути клацань у звуці.

## Етапи впровадження

### Етап 1: Перевірка стабільності (PoC)
Перед написанням основного коду необхідно провести тест:
- Створити скрипт, що підключається до `https://online.kissfm.ua/KissFM_HD`.
- Відтворювати потік безперервно протягом 30 хвилин.
- **Критерії успіху:** відсутність витоку пам'яті, стабільний рівень буфера, коректна робота `AudioSystem` з нескінченним потоком.

### Етап 2: Зміни в БД та Сервісах
- Додати міграцію для таблиці `radio_stations`.
- Оновити `AudioService`, щоб він міг приймати URL замість `File`.
- Додати `RadioStationService` для роботи з API та JSON-кешем.

### Етап 3: Оновлення UI
- **MediaEventEditorDialog**: Додати режим "Радіостанція" з вибором зі списку "Вибраного".
- **RadioCatalogDialog**: Вікно для пошуку станцій у локальному JSON-кеші та додавання їх у "Вибране".

## Переваги для користувача
1. **Зручність:** Пошук станції за назвою ("Хіт FM", "Байрактар") замість пошуку посилань в інтернеті.
2. **Надійність:** Система автоматично відновлює звук при збоях інтернету.
3. **Естетика:** Використання логотипів станцій (favicons) у списку розкладу.

## Висновок
Гібридний підхід (JSON-каталог + SQLite-вибране) є найбільш збалансованим. Він забезпечує максимальний вибір для користувача при мінімальному навантаженні на систему та високій стабільності розкладу.
