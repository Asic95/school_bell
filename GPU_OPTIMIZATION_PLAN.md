# План оптимізації навантаження на GPU (School Bell)

Цей документ описує стратегії зменшення споживання ресурсів відеокарти (GPU) та загального навантаження на систему для JavaFX додатку.

## 1. Робота з анімаціями та ефектами
- **Мінімізація Blur та Shadow:** Ефекти `DropShadow` та `InnerShadow` з великим радіусом розмиття (`radius > 10`) дуже сильно навантажують GPU.
    - *Рішення:* Використовувати статичні зображення тіней для повторюваних елементів або зменшити `radius`.
- **Вимкнення пульсуючих анімацій:** Постійні анімації (наприклад, пульсація статусу "LIVE" в `EfirView`) змушують JavaFX перемальовувати сцену 60 разів на секунду.
    - *Рішення:* Замінити пульсацію на статичний яскравий колір або дуже повільну зміну прозорості.
- **Оптимізація переходів (Transitions):** Використовувати `FadeTransition` замість `Scale` або `Translate` там, де це можливо, оскільки зміна прозорості зазвичай менш витратна.

## 2. Кешування вузлів (Node Caching)
- **Використання `setCache(true)`:** Для складних компонентів (карток, фонів з градієнтами), які рідко змінюються, слід увімкнути кешування.
    ```java
    node.setCache(true);
    node.setCacheHint(CacheHint.SPEED);
    ```
- **Кешування фонів:** Складні градієнти (як у `COLOR_BG`) краще рендерити один раз і зберігати як бітмап.

## 3. Частота оновлення UI
- **Throttle для таймерів:** Переконатися, що таймери оновлення часу (секунди) не ініціюють повне перемальовування всієї сторінки.
    - *Рішення:* Оновлювати лише конкретний `Label`, а не весь контейнер.
- **Оновлення списків:** При оновленні списків пристроїв або оголошень використовувати `setAll()` замість `clear()` + `addAll()`, щоб мінімізувати кількість подій зміни лейауту.

## 4. Оптимізація графіки та SVG
- **Спрощення SVG шляхів:** Дуже складні іконки з тисячами точок споживають ресурси при кожному масштабуванні.
    - *Рішення:* Використовувати спрощені версії іконок.
- **ICON_SCALE:** Перевірити, чи не занадто часто викликається метод масштабування SVG у `UIComponents`.

## 5. CSS та стилізація
- **Уникати `-fx-background-color: linear-gradient(...)` у циклах:** Градієнти краще виносити у статичні константи стилів (як це вже зроблено в `UIStyles`), щоб уникнути постійного парсингу рядків.
- **Спрощення заокруглень:** Дуже великі радіуси заокруглення (`-fx-background-radius`) на великих поверхнях з ефектами прозорості (Glass UI) можуть бути витратними.

## 6. Результати міні-експертизи та оцінка ризиків

### А. Напівпрозорість (Transparency Blending)
- **Ризик:** 5% (Мінімальний).
- **Вплив:** Зникне легкий "скляний" ефект фону.
- *Рекомендація:* Замінити `rgba(255, 255, 255, 0.96)` на `#ffffff`.

### Б. Екстремальні радіуси тіней
- **Ризик:** 2% (Дуже низький).
- **Вплив:** Тіні стануть менш розмитими, інтерфейс виглядатиме "зібранішим".
- *Рекомендація:* Зменшити радіус тіні з `30` до `15` або `10`.

### В. Конфлікт кешування (Cache Invalidation)
- **Ризик:** 15% (Середній).
- **Вплив:** Якщо помилитися з логікою, динамічні дані (час) можуть перестати оновлюватися візуально.
- *Рекомендація:* Вимкнути `setCache` для `timeCard` та `heroCard`.

### Г. Оптимізація ProgressBar та Label
- **Ризик:** 1% (Майже відсутній).
- **Вплив:** Тільки позитивний (зменшення викликів рендеру).
- *Рекомендація:* Додати перевірку `if (!newValue.equals(oldValue))`.

### Д. Повторне використання карток (Object Pooling)
- **Ризик:** 30% (Високий).
- **Вплив:** Потребує значного переписування логіки оновлення списків. Можливі помилки зі "старими" даними в картках.
- *Рекомендація:* Впроваджувати обережно, почати з `DeviceRow`.

### Е. Кешування SVG іконок
- **Ризик:** 10% (Низький).
- **Вплив:** При неправильній реалізації зміна кольору іконки (наприклад, при наведенні) може не спрацювати.
- *Рекомендація:* Використовувати `Map<String, SVGPath>` з урахуванням кольору як ключа.

## Пріоритетні кроки (від найбезпечніших):
1. **[Низький ризик]** Оптимізація `ProgressBar` та `Label`.
2. **[Низький ризик]** Зменшення радіусів тіней у `UIStyles.java`.
3. **[Низький ризик]** Заміна `GLASS_WHITE` на непрозорий колір.
4. **[Середній ризик]** Ревізія `setCache` (вимкнення там, де є годинник).
5. **[Високий ризик]** Кешування SVG та Object Pooling для списків.
