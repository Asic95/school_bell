# Стратегія: Система автоматичного оновлення (OTA) - Повна документація

## 1. Огляд
School Bell використовує безшовну систему оновлення "по повітрю" (OTA), розроблену для максимальної зручності користувача та повної автоматизації розробника. Система базується на філософії "Зібрав один раз — опублікував усюди".

---

## 2. Робочий процес розробника (Публікація)

Усі кроки публікації об'єднані в один скрипт PowerShell: `publish_release.ps1`.

### 2.1. Попередні вимоги
- **GitHub CLI (`gh`):** Встановлений та авторизований через `gh auth login`.
- **Git:** Усі зміни коду мають бути зафіксовані (commit) перед запуском скрипта.

### 2.2. Випуск нової версії однією командою
Щоб випустити нову версію, виконайте:
```powershell
./publish_release.ps1 -Version "1.2.0" -Changelog "Опис нових функцій та виправлень"
```

### 2.3. Що скрипт робить автоматично:
1.  **Синхронізація версій:** Оновлює рядок версії у наступних файлах:
    - `src/main/java/com/schoolbell/MainApp.java` (Логіка програми)
    - `pom.xml` (Проект Maven)
    - `build_dist.ps1` (Конфігурація збірки)
    - `schoolbell_installer.iss` (Скрипт Inno Setup)
2.  **Компіляція та пакування:** Запускає Maven для створення JAR та Inno Setup для створення інсталятора `.exe`.
3.  **Безпека:** Розраховує **контрольну суму SHA-256** нового інсталятора.
4.  **GitHub Реліз:** 
    - Створює новий тег та реліз на GitHub.
    - Завантажує інсталятор `.exe` як актив релізу.
5.  **Оновлення маніфесту:** Створює/оновлює файл `updates.json` з деталями нової версії, прямим посиланням на завантаження та хешем.
6.  **Git Push:** Фіксує всі оновлені файли та відправляє їх у вашу поточну гілку (наприклад, `master`).

## 3. Життєвий цикл клієнта (Оновлення)

### 3.1. Виявлення
- **Тригер:** При запуску програми + кожні 24 години + ручна перевірка в Налаштуваннях.
- **Маніфест:** Завантажує `updates.json` з гілки `master` вашого репозиторію GitHub.
- **Логування:** Усі кроки (перевірка, статус сервера, порівняння версій) записуються в **Журнал системних подій** в інтерфейсі програми.

### 3.2. Фонове завантаження
- **UI:** Преміальне вікно `UpdateAvailableDialog` показує список змін та прогрес-бар.
- **Прогрес-бар:** Високоякісний градієнт Indigo-Violet зі спеціальною підкладкою у стилі Soft UI.
- **Валідація:** Після завантаження у тимчасову папку програма перевіряє SHA-256 хеш. Якщо він не збігається, файл видаляється задля безпеки.

### 3.3. Безшовне встановлення ("Заміна")
1.  Програма запускає інсталятор з прапорцями: `/VERYSILENT /CLOSEAPPLICATIONS /RESTARTAPPLICATIONS`.
2.  **`AppMutex`:** Інсталятор виявляє запущену програму `SchoolBell.exe` (навіть якщо вона в треї) і дає сигнал на закриття.
3.  **Тихе оновлення:** Файли замінюються без відображення складних вікон майстра встановлення.
4.  **Авто-перезапуск:** Після завершення інсталятор автоматично знову запускає School Bell вже нової версії.

## 4. Вирішення проблем та обслуговування

### 4.1. URL-адреса маніфесту
Файл `UpdateService.java` посилається на:
`https://raw.githubusercontent.com/Asic95/school_bell/master/updates.json`
*Примітка: Якщо ви перейменуєте репозиторій або зміните гілку, цю адресу потрібно буде оновити в коді.*

### 4.2. Кешування GitHub
Контент GitHub Raw може кешуватися приблизно на 5 хвилин. Якщо оновлення не з'являється відразу після публікації, зачекайте кілька хвилин і перезапустіть програму.

### 4.3. Очищення
Інсталятор `.exe` завантажується в тимчасову директорію системи. Вона керується ОС Windows і зазвичай очищується автоматично або замінюється при наступному оновленні.

## 5. Стандарти безпеки
- **Тільки HTTPS:** Усі комунікації використовують шифрування TLS.
- **Перевірка контрольної суми:** Обов'язкова для кожного завантаження.
- **Безпека тихого режиму:** Прапор `/VERYSILENT` використовується лише для перевірених завантажених файлів, ініційованих користувачем.
