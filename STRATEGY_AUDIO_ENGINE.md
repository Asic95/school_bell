# План модернізації аудіо-рушія School Bell

Цей документ описує стратегію переходу від нестабільного JavaFX MediaPlayer до універсального PCM-рушія для гарантованого відтворення будь-яких MP3/WAV файлів на обраних аудіо-пристроях.

## 1. Аналіз проблеми
Поточна реалізація використовує `javafx.scene.media.MediaPlayer` для MP3-файлів. Це призводить до:
*   **Випадкових збоїв**: MediaPlayer не підтримує деякі профілі MP3 (VBR, високі бітрейти, специфічні теги).
*   **Обмеження пристроїв**: MediaPlayer завжди грає через системний аудіо-вихід "за замовчуванням", ігноруючи вибір користувача в налаштуваннях.
*   **"Німого" відтворення**: Файл ніби завантажений, але звук не декодується коректно.

## 2. Цільове рішення: Universal PCM Engine
Ми перейдемо на пряме керування байтами звуку через Java Sound API (`SourceDataLine`). Програма буде самостійно розпаковувати MP3 в PCM (сирий звук) і відправляти його в потрібний "мікшер".

### Переваги:
*   **100% сумісність**: Підтримка будь-яких MP3 файлів.
*   **Гнучкість**: Відтворення MP3 через будь-яку обрану USB-карту чи динаміки.
*   **Професійний Fade**: Програмне керування гучністю (Software Volume Control) забезпечує ідеально плавне затихання без ривків.

## 3. Крок 1: Оновлення залежностей (pom.xml)
Необхідно додати бібліотеки для декодування MP3:

```xml
<!-- MP3 Decoding Support -->
<dependency>
    <groupId>javazoom</groupId>
    <artifactId>jlayer</artifactId>
    <version>1.0.1</version>
</dependency>
<dependency>
    <groupId>com.googlecode.soundlibs</groupId>
    <artifactId>mp3spi</artifactId>
    <version>1.9.5.4</version>
</dependency>
```

## 4. Крок 2: Рефакторинг AudioService.java
Нова логіка методу `playAudioFile` має працювати за таким алгоритмом:

1.  **Визначення пристрою**: Отримати `Mixer.Info` для обраного користувачем девайса.
2.  **Відкриття потоку**: Використати `AudioSystem.getAudioInputStream(file)`. Завдяки `MP3SPI`, Java побачить MP3 як звичайний аудіо-потік.
3.  **Конвертація в PCM**: Якщо файл у форматі MP3 (MPEG), конвертувати його "на льоту" у стандартний PCM (44.1kHz, 16-bit, Stereo).
4.  **Створення власного буфера**: Читати байти з файлу частинами по 4096 байт.
5.  **Software Volume Control**: Перед відправкою кожного буфера на колонки, множити значення амплітуди байтів на коефіцієнт гучності (від 0.0 до 1.0). Це дозволить:
    *   Робити плавний старт (Fade-in).
    *   Робити плавне завершення (Fade-out).
    *   Тримати стабільний рівень гучності незалежно від системних повзунків Windows.
6.  **Вивід у Line**: Записувати оброблені байти в `SourceDataLine` обраного мікшера.

## 5. Крок 3: Плавне зупинення (Fade-out)
Метод `stopAll()` тепер не просто "вимикатиме" звук, а встановлюватиме прапорець `isStopping`. Потік відтворення за 2-3 секунди плавно зменшить множник гучності до нуля і лише тоді закриє аудіо-лінію.

## 6. Як впровадити (Інструкція для Gemini)
Коли буде достатньо ресурсів, надішли цей файл мені з командою:
*"Реалізуй план згідно з документом STRATEGY_AUDIO_ENGINE.md. Почни з оновлення pom.xml, потім перепиши AudioService.java, видаливши використання javafx.scene.media.MediaPlayer та впровадивши програмне мікшування PCM з підтримкою обраного Mixer.Info."*
