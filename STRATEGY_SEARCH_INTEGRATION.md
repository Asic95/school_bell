# План інтеграції універсального пошуку в School Bell

Цей документ описує стратегію додавання полів пошуку на сторінки керування базовими сутностями школи для покращення UX та швидкості роботи з великими обсягами даних.

## 1. Цільові сторінки
Пошук необхідно впровадити в наступні компоненти:
1.  **Викладацький склад** (`TeachersEditorTab.java`)
2.  **Навчальні дисципліни** (`SubjectsEditorTab.java`)
3.  **Шкільні класи** (`ClassesEditorTab.java`)
4.  **Навчальні аудиторії** (`ClassroomsEditorTab.java`)

## 2. Дизайн-код (UI/UX)
Згідно з концепцією "Modern Academic Soft UI v2", поле пошуку повинно:
*   Використовувати стиль `PREMIUM_FIELD_STYLE`.
*   Розміщуватися у верхній частині сторінки (Action Toolbar) поруч із кнопкою додавання.
*   Мати іконку пошуку (`ICON_SEARCH`) та плейсхолдер ("Пошук за назвою...", "Пошук вчителя...").
*   Оснащуватися кнопкою очищення, якщо введено текст.

## 3. Технічна реалізація

### Крок 1: Додавання змінної стану
В кожному класі Tab-а додати:
```java
private String searchText = "";
```

### Крок 2: Створення UI елемента
У методі `createContent()` додати поле пошуку:
```java
TextField searchField = new TextField();
searchField.setPromptText("Пошук...");
searchField.setStyle(PREMIUM_FIELD_STYLE);
searchField.setPrefWidth(300);
searchField.textProperty().addListener((o, ov, nv) -> {
    this.searchText = nv.toLowerCase().trim();
    refreshData(); // Виклик методу оновлення списку
});
```

### Крок 3: Модифікація логіки фільтрації
Методи оновлення списків (наприклад, `refreshTeachers()`) мають бути змінені для підтримки предикатів:
```java
List<Entity> filtered = allEntities.stream()
    .filter(e -> e.getName().toLowerCase().contains(searchText))
    .toList();

if (filtered.isEmpty() && !searchText.isEmpty()) {
    container.getChildren().add(createEmptyState(ICON_SEARCH, "Нічого не знайдено", "Спробуйте змінити запит"));
} else {
    // Відображення відфільтрованих карток/рядків
}
```

## 4. Специфіка для конкретних сторінок
*   **Teachers**: Пошук має працювати не лише за ПІБ, а й за предметами, які закріплені за вчителем.
*   **Classes**: Пошук має підтримувати числові та текстові запити (наприклад "9" або "9-А").
*   **Substitutions**: (Вже реалізовано) - пошук за двома вчителями та класом.

## 5. Як впровадити (Інструкція для Gemini)
Коли буде достатньо ресурсів, надішли цей файл мені з командою:
*"Реалізуй план згідно з документом STRATEGY_SEARCH_INTEGRATION.md. Додай поля пошуку на сторінки вчителів, предметів, класів та аудиторій. Забезпеч миттєву фільтрацію та дотримуйся стилістики PREMIUM_FIELD_STYLE для полів вводу."*
